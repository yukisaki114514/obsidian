# ColliderFit スカート用メモ（2026-11-16）

## 位置づけ（決定事項）

- GrokがX検索をもとに提案した改変ツール案12件（2026-11-16）は、競合監査の結果**全て捨てる**。
  - 理由の要約：ParamPrioritizer ≒ Parameter Bit Saver＋IntParameterCompressor、NonCompatibleAligner ≒ WearFit／もちふぃった～／Alterith、AnimatorTransitionCopy ≒ Better Animator Transition Copy（無料）、QuestCompatChecker ≒ VRCQuestTools、ExpressionMenuBuilder ≒ AvatarMenuCreator for MA、MaterialSlotAuditor ≒ AAO／lilAvatarUtils。加えてGrok結果には投稿URL・日付・件数が一切なく、頻度評価が検証不能だった。
- 唯一残すのは **SkirtPhysBoneHelper の素材だけ**。ただし**単体新作にはしない**。ColliderFitの将来候補（v1.x以降）として本メモに吸収する。
- **v1.0.0のスコープは変更しない。** 前提は従来どおり：受け入れテスト8項目（まず1〜4）を実機で通すことが先で、それまで価格・出品の議論も、新機能の実装もしない。価格の条件付き意向（全テスト通過後に480円程度）も不変。

## スカートで困っていること（素材）

- フルトラで座ったときに脚がスカートを貫通する、前後移動でスカートがめくれ上がる、片脚だけ貫通する、といった症状が繰り返し言及される。
- 直し方の定石は PhysBone 本体の調整ではなく、まず **UpperLeg（左右）に置く PhysBoneCollider の大きさ・位置** と、スカート側 PhysBone への **登録漏れの有無**。
  - 公開ガイドの数値例（2026-11-16確認）：Capsule、Radius 0.05〜0.08／Height 0.2〜0.3（かける氏の2026.4版ノート）、別ガイドでは Radius 0.09／Height 0.42。**アバターにより値が大きく違うので、固定プリセット値の配布ではなく「実メッシュから算出した初期値」がColliderFitの価値**になる。
  - スカート側 PhysBone の設定例（Limit Hinge、Max Angle 40〜50、Immobile 0.7〜0.9＋カーブ、Radiusは根元小さく先端大きく）はコライダーではなく PhysBone パラメータ調整であり、**ColliderFitの対象外**（下記スコープ境界参照）。

## ColliderFitへの吸収案（将来候補・未決定）

1. **脚コライダーのスカート用途を明示する**
   - 既存の計測コア（実メッシュから半径・位置を算出）で UpperLeg 左右のカプセルを算出する用途を、readme／デモで「スカート貫通対策」として打ち出す。新規コードなしで訴求だけ足すのが最小コスト。
2. **登録漏れ検出のスカート適用**
   - 既存の登録漏れ検出で「スカートの PhysBone に脚コライダーが登録されていない」を警告対象として確認する。登録は従来どおり個別実行のみ、一括で黙って入れない。
3. **（検討のみ）スカート用ラベル／プリセット名**
   - 算出結果の提示時に「スカート用」ラベルを付ける程度に留める。固定数値プリセットの適用機能は作らない（アバター差が大きく、誤適用とサポートの温床になる）。

## スコープ境界（約束しないこと）

- 「貫通ゼロ」は約束しない。PhysBoneコライダーはボーンチェーンとだけ作用する、という従来の正直なスコープをスカートでも維持する。売りは初期値算出と登録漏れ検出に限定。
- PhysBoneパラメータ（Limit、Immobile、Radiusカーブ等）の自動調整は v1 系の対象外。やるなら別途、設計案の承認から始める。
- コライダーを登録しすぎると Collision Check Count が増えてパフォーマンスランクが落ちるため、「当たる可能性のある PhysBone にだけ登録する」旨の注意を打ち出しに含める。

## リスク・未検証

- スカートのボーン構造（円周ボーンの本数・法線の向き）はアバター／衣装ごとに差が大きく、PhysBoneコンポーネント数が激増するケースもある。実機のスカート付きアバターでの確認なしに訴求を強めない。
- PhysBone には Version 1.0／1.1 があり Gravity／Stiffness の意味が異なる。コライダー算出に直接は影響しないが、サポート時の切り分け材料として覚えておく。
- 本メモ自体はコード監査ではなく、公開ガイド（2026-11-16検索確認）とGrok素材に基づく机上メモ。実機で検証できたこととは区別する。
