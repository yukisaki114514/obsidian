## 2. 判定パイプライン（優先順は固定）

1. **手動ロック**：`manual.locked`。自動判定は `manual` に一切書き込みません。
2. **辞書照合（第 1 層）**
   - ユーザー辞書の指紋で照合します。
     - 完全一致が 1 件だけなら、そのラベルで確定します（信頼度は高）。
     - 完全一致が複数ある場合や、部分一致は、候補として残すだけで確定しません。
   - 次に同梱ルールで照合します。
     - 名前と構成の両方が合えば高、名前だけなら中です。
3. **中身推定（第 2 層）**：シグナルの強さで決めます。
   - 強シグナルがあれば高です。ただし、別のラベルを指す強シグナルがほかにもあれば中に下げます。
   - 中シグナルだけなら中です。
   - 弱シグナルだけなら低です。
   - 材料が無ければ「不明」にして、理由を残します。

レコードには `inference`（第 2 層の結果）、`registry`（候補）、`auto`（最終結果と決定層 `layer`）、`manual` を別々に保存します。

### 走査単位（フェーズ0の代わりに置いた仮の方式）

- 基本の単位は Assets 直下のフォルダです。
- 次の条件をすべて満たすフォルダは「まとめフォルダ」（作者名フォルダ等）とみなし、中のフォルダを単位にします。
  - サブフォルダが 2 つ以上ある
  - 直下に置かれた中身のファイルが 3 件以下
  - asmdef も package.json も無い
  - サブフォルダの半分以上が Textures／FBX／Prefab 等の「製品の内部構造らしい名前」ではない
- `Plugins`／`Resources`／`StreamingAssets` は常にまとめフォルダとして扱います。
- まとめフォルダのラベルは子フォルダの集約です。全員が同じラベルならそのラベル、混在していれば「その他・低」にします。
- Assets 直下にばら撒かれたファイルは 1 行にまとめて「不明」として表示し、黙って捨てません。
- 走査単位より深いフォルダに付いた手動ラベルも、GUID で追跡を続けます。
- **この方式が実プロジェクトで妥当かは未検証です**（フェーズ0の項目1）。

### アバター判定と Prefab の負荷対策

- Prefab は、まず YAML テキストとして読みます。`LoadAssetAtPath` ではないので軽い処理です。
  - VRC Avatar Descriptor 固有のフィールド名（`ViewPosition:`、`VisemeSkinnedMesh:`、`baseAnimationLayers:` など 8 種）のうち 4 種以上がそろえば、Descriptor の候補にします。
  - Variant は `m_SourcePrefab` の GUID から元 Prefab をたどり（最大 6 段）、テキストだけで判断します。
- SDK がある場合は、候補だけを 1 フォルダ 10 件まで `LoadAssetAtPath<GameObject>` で読み込み、コンポーネントの型名で確定します（強シグナル）。
  - `Instantiate` も `SetDirty` もしません。
  - 走査の最後に `EditorUtility.UnloadUnusedAssetsImmediate()` を呼び、読み込んだアセットをメモリから外します。
- SDK が無い場合は、テキストでの判断だけになり、信頼度は中までです。
- 他フォルダのアバターを元にした Variant しか無いフォルダは、アバター本体ではなく衣装の中シグナルにします（着せ替え済み Prefab への対策）。
- モデル（FBX 等）は、1 フォルダ 3 件まで読み込んで Skinned Mesh の有無を確認します。

### 差分走査

- 依頼書にある AssetPostprocessor は **採用しませんでした**。
  - 理由：Postprocessor の追加や変更は、プロジェクト全体の再インポートを引き起こす可能性があります。読み取り専用ツールとして、その危険を避けました。
- 代わりに、各フォルダの「相対パス・サイズ・更新日時」の SHA1 を署名として保存します。差分走査では、署名が変わったフォルダだけ中身の推定をやり直します。
  - ファイルの列挙は毎回行います。重いのは推定の方なので、列挙のコストは許容しています。
- プロジェクトに変更があったことは `EditorApplication.projectChanged` で検知し、「差分走査で更新できます」と表示します。

## 3. 辞書照合（照合キー）

- 指紋は「登録フォルダからの相対パス + サイズ + GUID（取れる場合）」の集合です。絶対パスは保存しません。読み込み時と保存時に、`:` を含むパス、先頭が `/` のパス、`..` を含むパスを除外します。
- 照合キーは 3 種類で、一致率が最も高いものを採用します。
  - GUID
  - 相対パス
    - サイズの一致も求めます。
    - ただし `.prefab`／`.mat`／`.anim` 等の再シリアライズされやすいアセットは、パスの一致だけで数えます。
  - ファイル名 + サイズ
    - フォルダ構成が変わっていても当たるキーです。
    - このキーだけで当たった場合は、完全一致にしません。
- 判定基準
  - **完全一致**：辞書側のファイルが 100% そろい、かつフォルダ側にも余分なファイルが無い。
  - **部分一致**：辞書側ファイルの 80% 以上（設定で変更可）がそろい、かつ辞書側のファイル数が 3 件以上。
- 入れ子の抑制：子フォルダで当たっている登録は、親のまとめフォルダには候補として出しません。
- unitypackage からの登録
  - tar を自前で読み、`pathname` と `asset` のサイズと GUID を取り出します。
  - 共通の親フォルダを登録の起点にします。
  - パッケージが Assets 直下の複数フォルダにまたがる場合は、フォルダごとに分けて登録します。

## 4. データ形式

- 索引：`<プロジェクト>/FolderLabeler/index.json`
  - フィールド：`format: "FolderLabeler.Index"`、`formatVersion: 1`、`folders[]`（GUID がキー）
  - 自分より新しい版数のファイルや、読めないファイルは上書きしません（手動ラベルを守るため、保存を止めます）。
- 辞書：既定は `%AppData%/Znakisaki/FolderLabeler/registry.json`
  - フィールド：`format: "FolderLabeler.Registry"`、`formatVersion: 1`、`settings`、`entries[]`
- どちらも一時ファイルに書いてから置き換えます。
- 辞書の場所の設定だけは EditorPrefs に保存します（キー `Znakisaki.FolderLabeler.RegistryPath`）。依頼書の書き込み先 3 か所の外になるため、readme に明記しました。

| 項目 | 変更 | 理由 |

| フェーズ0 | 未実施 | 開発者の指示 |

| 2 | 走査してもシーンが dirty にならない／タイムスタンプが変わらない | **未実施**（コード上は SetDirty・保存・Refresh・Instantiate を呼んでいないことを確認済み） |
| 3 | 手動ラベルが移動・改名の後も GUID で残る | **未実施**（GUID をキーにし、`GUIDToAssetPath` でパスを引き直す実装） |
| 4 | 索引 JSON を消すと初回状態に戻る | **未実施** |
| 5 | 数千件規模のプロジェクトでの所要時間 | **未実施** |
| 6 | アバター本体（高）・ツール（高）・不明（理由つき）の判定 | **一部実施**：ツール（HandGestureFit のソース → ツール・高）、シェーダーのフォルダ → シェーダー・高、空フォルダ → 不明（理由つき）、画像のフォルダ → テクスチャ・中、を Mono 上で確認。アバター本体の判定は Unity が必要なため未実施 |
| 7 | プロジェクト A で登録 → B で認識 | **ロジックのみ実施**：ColliderFit の unitypackage を模擬導入したフォルダで、GUID による完全一致を確認 |
| 8 | 外部登録・改名して導入しても当たる | **ロジックのみ実施**：外部フォルダの指紋 → .meta 無しのコピーに相対パスで完全一致。改名したフォルダでも一致 |
| 9 | ユーザーがファイルを追加すると候補になる（自動確定しない） | **ロジックのみ実施**：ファイルを 1 件追加 → 部分一致（辞書側 100%・フォルダ側 89%）で `exact=false`。ファイルを 1 件編集した場合も部分一致（88%） |

単体テストは全部で 23 件で、すべて成功しました。上の表のほかに、次の項目を含みます。

- 無関係のツール同士が当たらないこと
- 親のまとめフォルダで候補が抑制されること
- 同梱ルールの名前と構成の判定
- 信頼度の決定（強シグナルの衝突は中、弱シグナルだけなら低）

テスト中に、強シグナルが衝突したときに信頼度を二重に下げてしまう不具合が 1 件見つかり、修正済みです。

## 7. 他環境で弱くなる箇所（実測ではなく推定）

- **フォルダ名のキーワード**：日英の一般語だけを入れています。作者名だけのフォルダでは当たりません。キーワードだけで決まったラベルは信頼度が低になります。
- **衣装と髪型と小物の見分け**：キーワード頼みです。決まらなければ衣装（中）になります。
- **まとめフォルダ判定**：サブフォルダ名の英日リストに依存しています。独自の構成（例：`Ver1.0/`、`Quest/`）では、製品フォルダをまとめフォルダと誤認する可能性があります。
- **Prefab のバイナリシリアライズ**（Force Text でないプロジェクト）：テキストでの判断ができず、SDK が無いとアバター判定ができません。
- **Packages フォルダ**（VCC で入れた MA／NDMF 等）：走査の対象外です。Assets に入れた旧形式のインフラだけを同梱ルールで拾います。

## 8. 実機確認のお願い（優先順）

1. Unity 2022.3.22f1 で導入し、コンパイルエラーが無いこと（SDK あり／なしの両方）
2. 全走査の後、開いているシーンにアスタリスク（未保存の印）が付かないこと
3. フォルダの改名・移動の後も手動ラベルが残ること
4. 実プロジェクトでの所要時間と、まとめフォルダ判定が妥当か
5. アバター本体の Prefab が「アバター本体・高」になること
