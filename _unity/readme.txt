==============================================================
 Folder Labeler  v1.0.0
 フォルダ整理の手がかりツール  Unity エディター拡張
==============================================================

Folder Labeler は、Unity プロジェクトの Assets 内のフォルダを自動で調べ、
「衣装」「アバター本体」「ツール」「インフラ」などのラベルを、
信頼度 (高 / 中 / 低) と根拠つきで提案する Unity エディター拡張です。

  ・BOOTH などから入れたアセットのフォルダが増えて、
    フォルダ名だけでは中身が分からなくなったときの整理の手がかりにできます。
  ・消してはいけないインフラ (VRChat SDK / Modular Avatar / lilToon など) を
    見分けやすくします。
  ・一度ラベルを確かめたアセットを「辞書」に登録しておくと、
    ほかのプロジェクトでも同じアセットを「登録済み」として見分けられます。

このツールは読み取り専用です。フォルダやアセットの移動・改名・削除は行いません。


■ はじめにお読みください (できること・できないこと)
--------------------------------------------------------------
  ・自動で付くラベルは「候補」です。正確さは保証しません。
    最終的な確認は、必ずご自身で行ってください。
  ・信頼度は割合 (%) ではなく、根拠の強さによる 3 段階 (高 / 中 / 低) です。
  ・判定できないフォルダは無理に分類せず「不明」とし、
    なぜ判定できなかったか (根拠不足の理由) を表示します。
  ・読み取れなかったフォルダや、判定中にエラーが出たフォルダも、
    理由つきで一覧に残します (黙って飛ばしません)。

  次のことは v1.0.0 ではできません。
  ・衣装の対応アバターの表示
  ・使っていないアセット / フォルダの検出
  ・Project ウィンドウへのラベル (バッジ) 表示
  ・フォルダやアセットの移動・改名・削除の手伝い
  ・複数のプロジェクトをまとめて見る機能

■ 動作環境
--------------------------------------------------------------
  ・Unity 2022.3 系 (2022.3.22f1 を想定。VRChat のアバター制作で指定されているバージョン)
  ・Windows
  ・VRChat SDK (Avatars) があると、アバター本体の判定が強くなります。
    ※ SDK が無いプロジェクトでも動作します。その場合はウィンドウに
       「SDK がないためアバター判定は弱くなります」と表示され、
       アバター本体の判定は Prefab の記述内容だけで行います (信頼度は「中」まで)。


■ 導入方法
--------------------------------------------------------------
  1. 作業前にプロジェクトのバックアップを取ってください。
  2. FolderLabeler_v1.0.0.unitypackage を Unity のウィンドウにドラッグ&ドロップし、
     「Import」を押します。
     (Assets/FolderLabeler フォルダが作られます)
  3. Unity のメニューに「Tools > Folder Labeler」が表示されれば導入完了です。

  アンインストールするときは「Assets/FolderLabeler」フォルダを削除してください。
  走査結果も消したいときは、下の「データの保存場所と消し方」もご覧ください。


■ 使い方
--------------------------------------------------------------
  1. メニュー「Tools > Folder Labeler」を開きます。

  2. 「全走査」を押します。
       Assets 直下のフォルダ (作者名のフォルダなど、複数の製品をまとめている
       フォルダの場合はその中のフォルダ) ごとに、ラベルが付いた一覧が表示されます。

  3. 一覧の見かた
       ・ラベル   [手動] が付いているものは、ご自身で確定したラベルです。
                  「*辞書候補」は、辞書に似たアセットが登録されている印です。
                  「(まとめ)」は作者名フォルダなどで、中のフォルダの結果をまとめた表示です。
       ・信頼度   高 / 中 / 低。「-」は不明です。
       ・列の見出しを押すと並べ替えられます。
       ・行を選ぶと、Project ウィンドウでそのフォルダが点滅して場所が分かります。
       ・上の検索欄・ラベル・信頼度で絞り込めます。

  4. 下の詳細欄で、次のことを確認できます。
       ・根拠       どの手がかりでそのラベルになったか ([強] [中] [弱])
       ・中身の内訳  種類ごとのファイル数と例 (5 件まで)
       ・辞書の候補  似ている登録と一致率

  5. ラベルを直すとき
       詳細欄でラベルを選び「このラベルで確定」を押すと、手動ラベルとして固定されます。
       手動ラベルは、走査し直しても自動判定で上書きされません。
       フォルダを移動・改名しても、ラベルはそのフォルダについていきます。
       元に戻したいときは「自動判定に戻す」を押してください。

  6. 「レビュー」タブ
       信頼度「低」・「不明」・辞書の候補があるフォルダ・読み取りエラーのフォルダだけを
       集めて表示します。上から順に確定していくと、整理が早く終わります。

  7. 「差分走査」
       前回の走査からファイルの構成が変わったフォルダだけ、中身の判定をやり直します。
       アセットを追加したあとなどに使ってください。


■ 辞書 (登録したアセットを別のプロジェクトでも見分ける)
--------------------------------------------------------------
  ラベルを確かめたアセットを辞書に登録しておくと、別のプロジェクトで同じアセットを
  見つけたとき「辞書と完全一致」として、そのラベルが自動で付きます。

  登録のしかた (3 通り)
    ・一覧でフォルダを選び、詳細欄の「このフォルダを辞書に登録…」
    ・「辞書」タブの「外部フォルダを登録…」
        プロジェクトの外にある元のフォルダ (展開済みのアセット) を指定します。
        ※ 選ぶのは、プロジェクトの Assets の中に入るのと同じ階層のフォルダ
           (製品のフォルダ) にしてください。
    ・「辞書」タブの「unitypackage から登録…」
        unitypackage の中身の一覧を読み取って登録します。
        プロジェクトへの展開 (インポート) はしません。

  照合のしかた
    ・ファイルの GUID・フォルダからの相対パス・ファイル名とサイズで照合します。
      フォルダの名前を変えたり、別の親フォルダに移したりしても当たります。
    ・完全一致 (同じファイルがそろっていて、余分なファイルも無い) のときだけ
      自動でラベルが付きます。
    ・自作のマテリアルを足したなど、一部が違うときは「候補」として一致率つきで表示し、
      自動では確定しません。詳細欄の「この候補で確定」で確定できます。
      (候補にする基準は「設定」タブで変更できます。初期値 80%)

  辞書には、各ファイルの相対パス・サイズ・GUID だけを保存します。
  PC 上のフォルダの場所 (ユーザー名などを含むパス) は保存しません。
  「書き出し…」「読み込み…」で、ほかの PC に持っていくこともできます。

  同梱ルール
    VRChat SDK / Modular Avatar / NDMF / lilToon / Poiyomi などのよく使われる
    インフラは、フォルダ名と中身の構成で見分ける「同梱ルール」が最初から入っています。
    (編集はできません。合わない場合は手動でラベルを確定してください)


■ データの保存場所と消し方
--------------------------------------------------------------
  このツールが書き込むのは次のファイルだけです。
  ご自身のアセットのフォルダの中にファイルを作ることはありません。

  ・索引 (このプロジェクトの走査結果と手動ラベル)
        プロジェクトのフォルダ直下 (Assets の外) の
        FolderLabeler/index.json
        「画面を開かずに走査する」機能 (下記) を使ったときは
        同じ場所に report.txt も作られます。
      消し方: 「設定」タブの「索引を削除して初期状態に戻す…」を押すか、
              Unity を閉じてから、プロジェクト直下の FolderLabeler フォルダを
              削除してください (Assets の中の FolderLabeler とは別のフォルダです)。
              削除すると手動ラベルも消えます。辞書は消えません。

  ・辞書 (すべてのプロジェクトで共通)
        %AppData%\Znakisaki\FolderLabeler\registry.json
        (「設定」タブで場所を変えられます)
      消し方: 上のファイルを削除してください。

  ・辞書の場所の設定
        変更した場合だけ、Unity の EditorPrefs に
        「Znakisaki.FolderLabeler.RegistryPath」として保存されます。
        「設定」タブの「既定の場所に戻す」で消えます。

  ・書き出したファイル
        「レポートを保存…」「書き出し…」で、ご自身が保存先に選んだファイル。

  ネットワーク通信や、ほかのアプリの起動は行いません。


■ 仕様・制限
--------------------------------------------------------------
  ・判定するのは Assets 直下のフォルダと、複数の製品をまとめているフォルダ
    (作者名フォルダなど) の中のフォルダまでです。それより深い位置の製品は、
    その親フォルダの一部として判定されます。
  ・1 つのフォルダに複数の製品が混ざっている場合は、正しく判定できないことがあります
    (詳細欄に「中身の種類が混在しています」と表示されます)。
  ・Packages フォルダ (VCC で入れたパッケージ) は対象外です。
  ・ラベルは 1 フォルダにつき 1 つです。
  ・アバター本体の判定のため、Prefab をまず文字として読み、
    VRC Avatar Descriptor らしい記述のある Prefab だけを読み込んで確認します
    (1 フォルダ 10 件まで。設定で変更できます)。
    Prefab をシーンに置いたり、内容を変更したりはしません。
  ・衣装・髪型・小物の見分けは、ボーン付きのモデルがあるかどうかと、
    フォルダ名・ファイル名のキーワードで行います。決め切れないときは
    「衣装」(信頼度 中) になります。
  ・アバター本体を元にした「着せ替え済み Prefab」だけが入っているフォルダは、
    衣装として判定されます。
  ・フォルダ名だけで判断した場合は、信頼度は「低」になります。
  ・Windows / Unity 2022.3 以外の環境での動作は確認していません。


■ 画面を開かずに走査する (上級者向け)
--------------------------------------------------------------
  コマンドラインから、画面を開かずに走査してレポートを書き出せます。
    Unity.exe -batchmode -projectPath <プロジェクトのフォルダ>
              -executeMethod FolderLabeler.Batch.ScanAndReport -quit
  結果は FolderLabeler/index.json と FolderLabeler/report.txt に書かれます。
